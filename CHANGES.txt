--- 3. WP SCHEDULED CAMPAIGN ---

  Jobs
  ----
  - app/Jobs/PublishWpScheduledPostJob.php
    * postToWordPress: Payload aligned with WordPress external API (Postman example): send status "publish" and schedule_time "Y-m-d H:i:s" only; plugin treats future schedule_time as scheduled (response status "future"). Removed date/schedule time/run_at duplication so posts schedule correctly instead of publishing immediately.
    * After create: prefer slug/permalink from API (link, permalink, url); if only remote_url (?p=ID) then try resolvePermalink() via WP REST GET /wp/v2/posts/{id} so report shows slug-based URL when possible.
  - app/Http/Controllers/Admin/WpScheduledCampaignController.php (store)
    * For "today or past" scheduled_date use now()+2 hours as scheduled_at so WordPress receives a future time and does not show "Missed schedule" (WP cron runs on visit). If +2h would fall on the next calendar day, cap to end of today so the post stays scheduled for today.
    * syncCampaign(id): Sync status from WordPress for all posts in campaign. Rate limited: once per campaign per 10 minutes (cache) so users cannot hit server repeatedly.
    * retryPost(postId): Reset failed/queued post and re-dispatch PublishWpScheduledPostJob. Rate limited: once per post per 3 minutes.
    * syncPost(postId): Sync status from WordPress for one post. Rate limited: once per post per 5 minutes.
    * SCHEDULE_BUFFER_MINUTES = 120: for "today or past" we set scheduled_at = now + 2 hours (capped to same day) so WordPress receives a future time and does not mark "Missed schedule"; manual sync is only for refreshing status, not to fix missed schedules.

  Models
  ------
  - app/Models/Admin/WpScheduledCampaignPost.php
    * getDisplayStatusAttribute: Accurate status: Failed, Queued, Live, Missed schedule (WP still "future" but schedule date passed), Scheduled. Uses remote_status + scheduled_date.
    * getCanRetryAttribute: true for queued/failed/publishing (so Retry button shows for those).
    * getCanSyncAttribute: true when remote_id is set (so Sync button shows).

  Controllers
  -----------
  - app/Http/Controllers/Admin/WpScheduledCampaignController.php
    * store(): After creating campaign and posts, automatically dispatches PublishWpScheduledPostJob for all queued posts (no "Run queue" click required for first run; scheduling happens during creation like previous campaign).
    * run(): Uses new dispatchQueuedPosts() helper; "Run queue" button kept for re-dispatching failed/queued posts only.
    * dispatchQueuedPosts(campaignId): New private helper; dispatches jobs for queued posts and sets campaign started_at/status running.
    * report(campaign_no, token): New. Public token-protected report page. Stats from display_status.
    * exportReport(campaign_no, token): New. Token-protected Excel export.
    * show(): Backfill report_token when missing.
    * index(): Backfill report_token when missing.
    * Uses Spatie\SimpleExcel\SimpleExcelWriter for export.

  Views
  -----
  - resources/views/admin/campaigns/wp-scheduled/show.blade.php
    * Added "View report page" and "Copy report page link" buttons (when report_token present).
    * Added "Sync status" button (campaign-level) to sync all posts from WordPress.
    * Actions column: View (remote URL), Sync (per post, when remote_id set), Retry (per post, when queued/failed/publishing).
    * Pushed copy.js for copy-link behaviour.
  - resources/views/admin/campaigns/wp-scheduled/report.blade.php
    * Stats: added "Missed schedule" card; Display (report) uses Live/Failed/Missed schedule/Scheduled with correct styling (orange for Missed).

  - resources/views/admin/campaigns/wp-scheduled/index.blade.php
    * Actions column: View (campaign) icon, Copy report link icon, View report page icon (same pattern as Schedule Campaign list).
    * Pushed copy.js for copy-link behaviour.

  - resources/views/admin/campaigns/wp-scheduled/report.blade.php (NEW)
    * Token-protected report view: campaign title, Export Excel button, stats (Total, Live, Queued (scheduled), Failed), table of posts (Sno, Scheduled Date, Domain, Article, Status, Display (report), WP status, Remote URL).

  Jobs
  ----
  - app/Jobs/SyncWpScheduledPostStatusJob.php
    * Tries external API (external/v1/posts/status/{id}) then WP REST (wp/v2/posts/{id}); updates remote_status and published_at; updates remote_url to permalink (link) when returned. Keeps status accurate for Live/Missed/Scheduled.

  Console / Schedule

  - routes/console.php: Schedule::command('wp-scheduled:sync-status')->hourly() so WP status syncs automatically.

  Routes

    * GET /campaign/post/wp-schedule/report/{campaign_no}/{token} -> admin.wp.schedule.campaign.report
