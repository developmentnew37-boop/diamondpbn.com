================================================================================
ROLE-BASED PERMISSIONS: MEMBERS CAN ONLY ADD ARTICLES, NOT CREATE CAMPAIGNS
================================================================================
All changes made to implement: "Members can only add articles; they are not
allowed to create campaigns. Similarly, permissions are restricted based on role."

--------------------------------------------------------------------------------
1. ROLE DEFINITIONS (existing, unchanged)
--------------------------------------------------------------------------------
- Super Admin (type = 0): Full access; can create campaigns, manage users, etc.
- Admin (type = 1): Can create campaigns; can manage own data; user management
  visibility as per existing rules.
- Member (type = 2): Can only add articles. Cannot create any campaigns.

--------------------------------------------------------------------------------
2. MODEL CHANGES
--------------------------------------------------------------------------------
File: app/Models/Admin.php

ADDED:
- canCreateCampaigns(): bool
  Returns true for Super Admin and Admin, false for Member.
  Used to gate campaign creation and to hide campaign-creation UI for Members.

  public function canCreateCampaigns(): bool
  {
      return in_array((int) $this->type, [self::SUPER_ADMIN, self::ADMIN], true);
  }

--------------------------------------------------------------------------------
3. NEW MIDDLEWARE
--------------------------------------------------------------------------------
File: app/Http/Middleware/Admin/CanCreateCampaigns.php (NEW)

- Checks that the authenticated admin can create campaigns (canCreateCampaigns()).
- If not (e.g. Member), redirects to admin.dashboard with error message:
  "You do not have permission to create campaigns. Members can only add articles."
- Registered in bootstrap/app.php as alias: 'can.create.campaigns'

--------------------------------------------------------------------------------
4. MIDDLEWARE REGISTRATION
--------------------------------------------------------------------------------
File: bootstrap/app.php

ADDED to $middleware->alias([...]):
  'can.create.campaigns' => \App\Http\Middleware\Admin\CanCreateCampaigns::class,

--------------------------------------------------------------------------------
5. CONTROLLER CHANGES (middleware applied to create/store)
--------------------------------------------------------------------------------
Each of the following controllers now has a constructor that applies
'can.create.campaigns' middleware to ALL actions (index, show, create, store,
edit, update, destroy). So Members cannot open any campaign page (including
reporting/list URLs); they are redirected to the dashboard with the permission
message.

- app/Http/Controllers/Admin/campaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/SidebarCampaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/HiddenLinkCampaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/ScheduleCampaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/WpScheduledCampaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/ScheduleSidebarCampaignController.php
  __construct(): $this->middleware('can.create.campaigns')->only(['create', 'store']);

- app/Http/Controllers/Admin/StickyPostCampaignController.php
  __construct(): $this->middleware('can.create.campaigns');

Effect: If a Member visits any campaign URL (e.g. /admin/campaign, /admin/campaign/create,
/admin/campaign/123), they are redirected to the dashboard with the error message above.
Members cannot see or access the Reporting section at all.

--------------------------------------------------------------------------------
6. SIDEBAR / NAVIGATION CHANGES
--------------------------------------------------------------------------------
File: resources/views/admin/include/sidebar.blade.php

- "Run Campaigns" submenu (PBN Post, PBN Sidebar Post, PBN Hidden Links create links):
  Wrapped in @if ($sidebarAdmin->canCreateCampaigns()). Members do not see this block.

- "Addons" section: "Sticky" link and "DripFeed" submenu (Schedule Post, WP Scheduled,
  Schedule Blogroll):
  Wrapped in @if ($sidebarAdmin->canCreateCampaigns()). Members do not see Sticky
  or DripFeed.

- "Reporting" section (PBN Post, Blogroll, Hidden Link, Sticky Post list pages):
  Wrapped in @if ($sidebarAdmin->canCreateCampaigns()). Members do not see Reporting;
  only users who can create campaigns can see and access campaign reporting/list pages.

- "Articles", "Add Articles", "Article Set", "Domains", "Profile" remain visible to all.

--------------------------------------------------------------------------------
7. CAMPAIGN LIST PAGE "CREATE CAMPAIGN" BUTTONS
--------------------------------------------------------------------------------
The following views show a "Create Campaign" (or similar) button in the page header.
That button is now wrapped in @if (Auth::guard('admin')->user()->canCreateCampaigns())
so Members do not see it when viewing campaign list pages.

- resources/views/admin/campaigns/pbn-post/campaign.blade.php
- resources/views/admin/campaigns/pbn-sidebar/sidebar-campaign.blade.php
- resources/views/admin/campaigns/pbn-hidden-links/hidden-links-campaign.blade.php
- resources/views/admin/campaigns/pbn-sidebar/schedule-sidebar-campaign.blade.php
- resources/views/admin/campaigns/wp-scheduled/index.blade.php
- resources/views/admin/campaigns/pbn-post/schedule-campaign.blade.php
- resources/views/admin/campaigns/sticky-post/campaign.blade.php

--------------------------------------------------------------------------------
8. ARTICLES: MEMBERS ALLOWED
--------------------------------------------------------------------------------
No changes were required for article permissions. Existing behaviour already allows:
- Non–Super Admin users (including Members) to add and manage their own articles
  (e.g. ArticleController index scopes by admin_id when !isSuperAdmin()).
Members retain access to:
- Articles list, Add Articles, Article Category, Article Language, Article Set.
